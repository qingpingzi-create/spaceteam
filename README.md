# 太空小队 · 反应力挑战

中文网页互动游戏，包含两关测试、综合评分、昵称、共享排行榜和历史成绩。游戏无需另行注册玩家账号；在线站点的访问权限由部署平台控制。所有视觉资源随项目提供，无需外部字体或图片。

直接双击 `打开游戏.cmd` 或打开 `dist/index.html` 仍可离线游戏并保存本机成绩；共享排行榜需要后端服务，不能仅靠 GitHub Pages 等静态托管实现。

## 昵称、排行榜与参与统计

- 开始正式挑战或练习前填写昵称（1～16 个字符），游戏中锁定该昵称；返回首页可更换。正式挑战完成后自动保存并上榜，失败时可重试。成绩页、本机记录和 CSV 导出均显示昵称。
- 游戏中逐题显示当前积分、得分增减和完成进度。当前积分 = 已完成题目的表现分 × 已完成题数 / 30，再四舍五入；30 题结束后与原最终评分完全一致。
- 侧栏实时榜单展示玩家附近位次，并高亮本人；每题结束后刷新预计名次，显示上升或下降多少位。预计名次按当前积分与历史最高分中较好的成绩计算，仅作本轮预览，不写入正式成绩或增加参与人数。
- 完整排行榜打开时每 5 秒自动刷新，显示位次变化。预览结果只在反馈、关卡说明或暂停时显示，避免在等待反应信号时重绘干扰测试。
- 榜单按空格键、鼠标、触屏分别排名。每位玩家每种方式只展示最高分；同分依次比较正确率、反应时间、达成时间。
- 所有已提交的正式成绩保存在数据库中。在“我的云端历史”选择本机昵称档案，可分页查看历次成绩。
- 同一浏览器的同一昵称使用相同的随机玩家令牌；修改昵称建立新档案。令牌仅在本机保存，数据库保存其 SHA-256 摘要，不在排行榜公开。
- 累计参与人数为提交过正式成绩的不同昵称档案数；同一玩家重复挑战不增加人数，三种方式合计去重。不同设备、不同浏览器或清除档案后的同一个自然人可能被分别计数。这个数字不是实名去重人数。
- 正式挑战次数统计成功保存的完整成绩。练习、中途退出和保存失败的成绩不计入。重复保存及网络重试使用同一次挑战 ID，不增加次数。网络异常不影响本机积分显示，榜单恢复后自动重试读取。
- 旧版匿名本机记录仍可查看，但不自动上传、不推算旧版参与人数。清除本机成绩不会删除云端记录。
- 服务器校验完整的 30 题结构和有效时间，重新计算分数，不采用客户端直接传来的总分。榜单用于游戏训练，不作为防作弊考试系统。

## 游戏

- 操作方式：空格键、鼠标、触屏。整轮只接受选择的操作方式，记录也按操作方式分别比较。
- 练习：3 次发射 + 5 次保护飞船；不评分、不存入记录。
- 正式：10 次发射 + 20 次保护飞船（14 个陨石、6 艘友军，顺序随机）。
- 信号前等待 1～2.5 秒；第一关响应窗口 1.8 秒，第二关 1.4 秒。
- 信号前操作算抢跑；信号后小于 100 ms 算预判；友军时操作算误点；目标超时算漏答。
- 暂停、切换标签页、窗口失焦时停止计时。已完成题目保留，未完成题目在继续后重新出题。
- 反馈音默认关闭，目标出现时不播放提示音。
- 本机最近 50 次正式成绩；可导出含每题记录的 UTF-8 CSV，Excel 可打开。

## 计分

设 A 为全部题目正确率（0～1），M 为有效反应时间中位数，D 为有效反应时间中位绝对偏差。

- 速度：50 × clamp((900 - M) / 650, 0, 1) × A；没有有效反应为 0。
- 准确性：35 × A。
- 稳定性：15 × clamp(1 - D / 250, 0, 1) × A；有效反应不足 3 次为 0。
- 总分为三项未取整分数相加后四舍五入。分项显示保留一位小数。

阈值为当前游戏规则，未经年级常模校准，不应解释为科学测定或年龄排名。设备和输入延迟会影响绝对反应时间；优先在同设备、同操作方式下比较个人变化。

## 预览与验证

安装 Node.js 24 或更新版本后：`node serve.cjs`，访问 http://127.0.0.1:4173。本机服务使用内置 SQLite，数据库保存在 `.local-data/scores.sqlite`，重启服务后保留数据；此数据库与在线网站数据库各自独立。

验证评分：`node verify.cjs`。

验证完整游戏流程：`node verify-flow.cjs`（虚拟 DOM 与时钟，覆盖挑战、练习、暂停、键盘与触屏及存储不可用情况）。

验证数据库与接口：`node verify-api.cjs`（真实 SQLite，覆盖服务器重算评分、只读实时排名预览、历史最佳保护、去重、并发重试、榜单、历史、分页和重启持久化）。

验证昵称与实时榜单：`node verify-cloud.cjs`（虚拟 DOM 连接真实 API，覆盖位次上升/下降、信号期间延迟重绘、五秒自动刷新、完成后自动保存、人数去重与响应丢失后的重试）。

## 在线部署

项目采用原生 HTML/CSS/JavaScript，无第三方运行时依赖。`dist/` 顶层保留可离线使用的页面；`server/api.mjs` 为后端实现。

`node build.cjs` 将页面、样式和脚本嵌入 Cloudflare Worker，生成 `dist/server/index.js`。Sites 的 `.openai/hosting.json` 需保留原项目 ID，删除 `static`，声明 `"d1": "DB"` 和 `"r2": null`。SQL 迁移位于 `drizzle/`，由 Sites 在发布时应用。

GitHub 仓库提供源码和数据库迁移，不包含站点私有身份配置、访问令牌或玩家数据库。仅上传源码不会自动启用 GitHub Pages 上的共享榜。
